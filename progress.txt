## Codebase Patterns
- Framework: Next.js (App Router)
- Styling: Tailwind CSS
- Language: TypeScript
- Testing: Vitest
- **xterm.js Integration Pattern**:
  - Use `'use client'` directive for terminal components (xterm requires DOM access)
  - Import xterm CSS globally via `@xterm/xterm/css/xterm.css`
  - Initialize terminal in useEffect to ensure DOM is ready
  - Store xterm instance in refs to avoid re-renders and enable cleanup
  - Load FitAddon for automatic resize-to-container behavior
  - Add window resize listener and cleanup on unmount
  - Wrap terminal in flex container with fixed header/footer for responsive layout
- **Third-Party Library Mocking**:
  - Mock modules at the top of test files using `vi.mock()`
  - Mock implementations should return default exports matching the module structure
  - Use mock functions (vi.fn()) to track calls and assert on behavior
  - Global mocks (window.addEventListener) require vi.stubGlobal() before render and vi.unstubAllGlobals() in afterEach

## Kalshi Trading Integration (PRODUCTION)
- **PRODUCTION MODE**: Live trading enabled with `api.kalshi.com`
- **Risk Management**: Daily loss limit ($5k), position limits (10 max), min edge (5%)
- **KalshiWidget**: Shows real balance, positions, P&L, and opportunities
- **API Routes**: `/api/kalshi/prod` for live data, `/api/kalshi/stats` for demo
- **Trading Team v2.0**: 3 specialized agents (Scout, Trader, Risk Overseer)
  - Scout: 60s interval, finds high-confidence opportunities (>60% or <40%)
  - Trader: 30s interval, executes trades with position sizing
  - Risk Overseer: 15s interval, monitors limits, only announces breaches

## Trading Team v2.0 - Optimized Architecture
- **Silent operation**: Only announces critical issues
- **Batched polling**: Coordinator pattern eliminated individual noise
- **Git commits**: Each successful trade/story triggers commit
- **Risk-first**: Trading halted on any breach, manual override required
